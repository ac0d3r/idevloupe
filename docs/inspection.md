# 验机原理

iDevLoupe 通过 USB 连接 iPhone，经系统的 usbmuxd 与设备上的 lockdownd 建立受信任的会话，
读取 iPhone 自己报告的信息，再逐项给出结论。不需要在手机上安装任何东西，也不联网。

## 判定原则

- 只有拿到正面证据才判「正常」；读不到或检查不完整一律「未知」，不会默认通过。
- 每项结论都附带依据；「原始数据」页展示设备返回的全部原值，便于复核。
- 回复与请求逐一核对（请求类型、服务名、domain/key、AFC 包序号），连接出错即作废重建，避免回复错位导致误判。
- 软件无法可靠判断的（部件是否原装、保修、运营商锁、外观等）列入「需人工核对」。

## 数据来源

| 来源 | 读到的内容 |
|---|---|
| lockdown 根域与各 domain | 型号、序列号、IMEI、地区、激活状态、查找、监管、电池、存储、iCloud 备份与同步等 |
| MobileGestalt | 颜色、型号等补充值，以及出厂配置记录 SysCfg（iOS 17.4 起不再提供） |
| IORegistry（diagnostics_relay） | 电池电量计、各部件当前报告的序列号与自检结果、存储控制器 |
| 系统分析日志 | 历史上记录过的电池循环次数与健康度 |
| installation_proxy / MCInstall / AFC | 已安装应用（越狱应用）、描述文件、afc2 服务 |

手机号、ICCID、IMSI 读到后立即丢弃，不进入报告；iCloud 同步只保留「是否为 iCloud」，不保留账户名。

## 各项检查

**锁与管理**：查找我的 iPhone（激活锁）、激活状态、监管模式、设备注册 / MDM、描述文件。

**部件**

- 出厂记录对比：SysCfg 里记有出厂时装入的电池、前后摄像头、屏幕面板、盖板玻璃、Touch ID 传感器的序列号，
  与部件现在报告的逐一对比。不一致说明换过；一致只说明前后吻合，不能证明原装——换屏时常把原序列号写进新屏，
  因此屏幕一致只作参考。
- 生产日期：部件序列号在供应商代码后编码了生产的年、周、星期。部件晚于整机生产日期（取自旧式序列号）
  就不可能是出厂装配的。这项不依赖出厂记录，各 iOS 版本都可用，但查不出取自更旧机器的部件。
- 面容 ID 自检：Pearl 驱动的自检码为 0 判正常，其它值提示手动测试。
- Touch ID：传感器报告序列号且出厂配对数据可用即视为正常，有自检结果时以自检为准。

**机器身份**：型号、机型类别（零售 / 工程机 / 内部版）、序列号与 IMEI 格式，以及 lockdown、MobileGestalt、
出厂记录三处的序列号与型号是否一致；网络地址与出厂记录不同说明换过主板或无线模块。

**系统**：越狱应用与 afc2 服务、启动参数、内部版 / 测试版系统等零售机不应有的设置。

**蜂窝网络**：基带状态与 SIM 卡托。

**电池**：健康度以 80% 为界（Apple 的服务标准），对照额定循环次数（iPhone 15 起 1000 次，之前 500 次）。
更换的证据：当前循环次数低于日志中曾记录的次数，或电芯生产日期晚于整机。没有证据不代表原装——
iOS 自己对部件是否原装的判断（「部件与维修历史」）无法通过数据线读取。

## 颜色与机型资料

颜色代码在不同机型间含义不同，颜色名、发布日期、电池厂商取自 3uTools 的设备表（`devices_table.txt`）：
优先用 `IDEVLOUPE_DEVICES_TABLE` 指定的文件或本机 3uTools 缓存，没有则用内置副本。
